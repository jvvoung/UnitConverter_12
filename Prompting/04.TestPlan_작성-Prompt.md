## Turn 1 — 테스트 계획서 작성 (`docs/test_plan.md`)

### User

```
[P] 시니어 QA 리드입니다.
[C] C++17, CMake, Catch2
[T] 선택한 샘플 예제(meter→feet 변환)를 기반으로 테스트 계획서를 작성해줘.

    포함 항목:
    - Catch2 기반 단위 테스트 범위/우선순위
    - 경계값 케이스 목록:
        · value = 0 (영값 변환)
        · value = 매우 큰 수 (오버플로 위험)
        · value < 0 (음수 입력 정책)
        · 소수점 파싱 실패 ("meter:abc")
        · ":"없는 입력 (형식 오류)
        · 없는 단위 ("parsec:1.0")
    - 예외/특이 케이스 목록
    - 커버리지 목표 (Domain 95%+ / Boundary 85%+)
    - # gcov / lcov / gcov UnitConverter.cpp 측정 전략

[F] docs폴더에 Markdown 문서. test_plan.md로 저장.
```

### Assistant (산출 요약)

- 선행 보고 [03.TestPlan_샘플예제_선정.md](../Report/03.TestPlan_샘플예제_선정.md), PRD, requirements, README, `UnitConverter.cpp` 교차 확인
- **앵커**: `meter:2.5` CONVERT(table) — `8.2 feet` / `2.7 yard` (1dp half-up)
- **§3 Catch2**: Domain/Boundary/Data/통합 4타깅, P0~P3 TC 17건, RED→GREEN 순서
- **§4 경계값**: BV-01~06 (0, 1e308, -2.5, abc, 형식, parsec) + Given-When-Then
- **§5 예외**: EX-01~16 (파싱·POL-NEG·POL-OUT·Mock·NG-03)
- **§6 커버리지**: Domain Line ≥95%/Branch ≥90%, Boundary Line ≥90%/Branch ≥85%
- **§7 gcov/lcov**: `ENABLE_COVERAGE`, 레거시 `gcov UnitConverter.cpp`, lcov extract·게이트
- 레거시 vs PRD 갭 — TC는 **목표 계약** 기준, RED FAIL 명시
- **산출 파일**: `docs/test_plan.md` (TP-2026-05-21-01)
