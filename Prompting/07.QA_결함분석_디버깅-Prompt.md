## Turn 1 — QA 결함 분석·디버깅

### User

```
[P] 디버깅과 결함 분석에 능한 C++ QA 엔지니어입니다.
[T] (여기에 cmake -S . -B build && cmake --build build 실패 로그를 붙여넣을 것)

    1) 테스트 실패의 기대/실제 차이 요약
       예: expected 8.202100 but got 0.000000
    2) 버그 위치 특정 (파일명:줄번호)
       예: UnitConverter.cpp:27
    3) 결함 심각도 분류 및 근거:
       Critical   — 변환 결과가 완전히 틀린 경우
       Major      — 경계값에서 오차 초과
       Minor      — 출력 포맷 불일치
       Info       — 코드 스타일/주석 문제
    4) 최소 변경 수정 방안 (C++ 스타일)
       - if-else 체인 유지 최소 수정 (GREEN 통과 우선)
       - Item/기본 구조체 수정 금지

[F] 수정 diff 제안 + cmake -S . -B build && cmake --build build Green 확인 절차
```

### Assistant (산출 요약)

- 실패 로그 **미첨부** → 로컬 `cmake -S . -B build && cmake --build build` · `ctest --test-dir build -C Debug --output-on-failure` 실행

- **과거 RED 이력** (`LastTestsFailed.log` #8, #13):
  - `test_convert_largeValue_returnsFiniteResult` · `test_convert_maxFiniteValue_staysWithinDoubleRange`
  - 원인: `1e308`/`1e200` × 3.28084 → double **Inf**
  - **이미 수정됨**: `1e50`/`1e100` (`domain_boundary_tests.cpp:28,93`) — D-01 **Closed**
- **레거시 CLI** (`meter:2.5` 수동 검증):
  - stdout: `8.2021 feet`, `2.73402 yard` (고정밀 3행, source unit 포함)
  - PRD AC-02 기대: `8.2 feet`, `2.7 yard` (table 1dp, source 제외)
- **잠재 결함 식별** (Catch2 미커버):
  - **D-02 Minor** — `UnitConverter.cpp:47-49` 출력 포맷 불일치
  - **D-03 Major** — `UnitConverter.cpp:23-28` POL-NEG(0·음수) 미검증
  - **Critical 패턴** (현재 해당 없음): feet/yard 분기 `meterValue` 미할당 → `0.000000`
