### 3.2 CMake 타깅 (실제 구성)

| 타깅 | 산출물 | 링크 | 비고 |
|------|--------|------|------|
| Domain | `unit_converter_domain` | — | Catalog·Engine·LengthQuantity |
| Boundary | `unit_converter_boundary` | → Domain | Parser·Validator·Formatter |
| Data | `unit_converter_data` | → Domain | JSON/YAML ConfigLoader |
| Domain 테스트 | `unit_converter_domain_tests` | Domain+Boundary+Data | 28 TC |
| Data 테스트 | `unit_converter_data_tests` | 동일 | 7 TC |
| CLI | `unit_converter_cli` | BCE libs + `UnitConverter.cpp` | 레거시 main, BCE 미연동 |

> test_plan의 **Domain 타깅 Boundary/Data 미링크** 원칙은, 별도 Domain-only 테스트 타깅 분리 시 엄격 적용 가능. 현재는 학습·통합 검증을 위해 Domain 테스트 exe가 Boundary/Data를 링크한다.

## 4. 구현 계약 요약

### 4.1 Domain (PRD §5.1)

| 단위 | `meters_per_unit` | 검증 TC |
|------|-------------------|---------|
| meter | 1.0 | 허브 기준 |
| feet | 0.3048 | `1 meter = 3.28084 feet` |
| yard | 0.9144 | `1 meter = 1.09361 yard` |

**환산식**: `target = source × (k_source / k_target)`

**API**:

- `UnitCatalog::add` / `registerUnit`
- `ConversionEngine::convert` / `convertAll`
- `LengthQuantity::create` — POL-NEG Domain 거부
- `bootstrap_default_three_units()`

### 4.2 Boundary (PRD §3.3)

| 컴포넌트 | 책임 |
|----------|------|
| `InputParser` | `unit:value` 파싱, INVALID_FORMAT / INVALID_NUMBER 메시지 |
| `ValueValidator` | `Value must be positive: {value}` |
| `TableFormatter` | table 1dp half-up (8.2, 2.7) |

### 4.3 Data (PRD §5.2)

| 기능 | 동작 |
|------|------|
| `ConfigLoader::loadFromFile` | JSON/YAML, `schema_version=1`, `base_unit=meter` |
| 실패 | `ConfigLoadError` — `Failed to load config: {path}` |
| fallback | 없음 (깨진 schema·빈 units → 예외) |

### 4.4 동적 등록 (PRD §5.3)

- `UnitCatalog::registerUnit("cubit", 0.4572)` 후 `cubit:2` → meter ≈ 0.9144
- 중복·k≤0 → `DuplicateUnitError` / `InvalidMetersPerUnitError`
