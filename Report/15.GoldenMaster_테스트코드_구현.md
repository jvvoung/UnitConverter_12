## 1. Executive Summary

[RPT-14](./14.GoldenMaster_회귀테스트_설계.md)에서 구축한 Golden Master Approval 인프라를 **요구 명세에 맞는 테스트 코드 형태**로 재구성하였다. 통합 2건 TC(`golden_master_cli_regression_matches_expected` / `golden_master_engine_baseline_document`)를 **시나리오별 4건 독립 TC**로 분리하고, CMake `add_test(NAME GoldenMaster COMMAND UnitConverter_test)` 단일 ctest 엔트리로 등록하였다.

| 구분 | RPT-14 (설계 세션) | 본 작업 후 |
|------|---------------------|------------|
| 테스트 소스 | `tests/golden_master_tests.cpp` | ✅ `tests/test_golden_master.cpp` |
| 테스트 exe | `unit_converter_golden_master_tests` | ✅ `UnitConverter_test` |
| ctest 등록 | `catch_discover_tests` 2건 (#50~#51) | ✅ `add_test(NAME GoldenMaster)` 1건 (#50) |
| Catch2 TC 수 | 2건 (통합 CLI + Engine) | **4건** (시나리오별 GM-TC-01~04) |
| diff 형식 | `L{n}` / `-` / `+` 라인 diff | ✅ unified diff (`--- expected` / `+++ actual` / `@@`) |
| 섹션 비교 | 전체 문서 일괄 비교 | ✅ `[scenario]` 블록 단위 추출·비교 |
| GoldenMaster ctest | 2/2 PASS | ✅ **1/1 PASS** (내부 4 TC · 8 assertion) |
| ctest 전체 | 50/51 | **49/50** (json RED 1건 유지) |

**핵심 결론**: 4개 입력 시나리오가 **독립 Catch2 TC**(`TEST_CASE_METHOD`)로 분리되어, 실패 시 **해당 시나리오 섹션만** unified diff로 표시된다. `ctest -R GoldenMaster` 단일 명령으로 4건 회귀를 일괄 실행할 수 있으며, baseline(`tests/golden_master_expected.txt`)은 RPT-14와 **동일**(레거시 CLI 6dp)을 유지한다.

## 3. 테스트 설계

### 3.1 Catch2 TC ↔ 시나리오 매핑

| TC ID | TEST_CASE_METHOD | 입력 | 기준 파일 섹션 |
|-------|------------------|------|----------------|
| GM-TC-01 | `UnitConverter_meter_2_5` | `meter:2.5` | `[meter:2.5]` |
| GM-TC-02 | `UnitConverter_feet_1_0` | `feet:1.0` | `[feet:1.0]` |
| GM-TC-03 | `UnitConverter_yard_1_0` | `yard:1.0` | `[yard:1.0]` |
| GM-TC-04 | `UnitConverter_meter_0_0` | `meter:0.0` | `[meter:0.0]` |

**태그**: `[GoldenMaster][GM-TC-0n]` — Catch2 필터 `[GoldenMaster]`로 개별 실행 가능.

### 3.2 GTest 요구 ↔ Catch2 구현 매핑

| 요구 (GTest 관례) | Catch2 구현 |
|-------------------|-------------|
| `TEST_F(GoldenMasterTest, ...)` | `TEST_CASE_METHOD(GoldenMasterTest, ...)` |
| `EXPECT_EQ(expected_str, actual_str)` | `expectSectionEquals()` — `expected_str != actual_str` 시 `FAIL` |
| `std::ifstream` 파일 읽기 | `golden_master::readTextFile(expected_path_)` |
| `./UnitConverter < input > output` | `captureCliStdout()` — Windows `cmd /c` redirect |

### 3.3 검증 흐름 (시나리오 1건)

```text
┌─────────────────────────────────────────┐
│ GoldenMasterTest fixture (생성자)        │
│  · CLI 경로 resolve (build/Debug 등)    │
│  · expected_path = golden_master_       │
│    expected.txt                         │
└──────────────────┬──────────────────────┘
                   ▼
     readTextFile(expected) → extractSection("[meter:2.5]")
                   │
     captureCliStdout(cli, "meter:2.5") → buildScenarioBlockFromCli
                   ▼
          expected_section == actual_section ?
               /                    \
             Yes                    No
              │                      │
              ▼                      ▼
           PASS              makeUnifiedDiff → FAIL
```

### 3.4 unified diff 출력 형식

불일치 시 Catch2 FAIL 메시지에 아래 형식이 포함된다:

```text
GM-TC-01 [meter:2.5] golden master mismatch.
--- expected
+++ actual
@@ -1,4 +1,4 @@
 [meter:2.5]
-2.5 meter = 8.202100 feet
+2.5 meter = 8.999999 feet
 ...
```
