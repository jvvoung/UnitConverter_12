## 1. Executive Summary

신규 **Bonus** 기능인 `DecayingUnit` 모듈에 대해 TDD **RED** 단계 테스트를 작성하였다. `registerUnit("cubit", 0.4572)` 기반 cubit↔meter/feet 변환·`convertAll`·음수 비율 거부·기존 meter→feet 회귀를 **6개 SECTION(BT-01~06)** 으로 고정하였으며, 구현은 **의도적 스텁**만 두어 **런타임 6/6 assertion FAIL** 로 RED를 확인하였다.

| 구분 | 작업 전 | 본 작업 후 |
|------|---------|------------|
| Bonus RED TC | 없음 | ✅ `TEST_CASE("감쇠 단위 변환", "[bonus]")` × 6 SECTION |
| `DecayingUnit` 모듈 | 없음 | ✅ `src/DecayingUnit.hpp` · `src/DecayingUnit.cpp` (스텁) |
| CMake 타깅 | domain/data/red/golden | ✅ **+ `unit_converter_bonus_tests`** |
| Bonus 빌드 | — | ✅ **성공** (스텁 링크 가능) |
| Bonus 테스트 | — | ❌ **6/6 FAIL** (의도적 RED) |
| BCE Domain `registerUnit` | GREEN (기존) | ✅ **변경 없음** |
| `UnitConverter.cpp` / `Item` (레거시) | REFACTOR 완료 | ✅ **미수정** |

**핵심 결론**: BCE `UnitCatalog`·`ConversionEngine`과 **분리된** Bonus 모듈에 대한 실행 가능한 RED 골격이 추가되었다. GREEN은 `DecayingUnit.cpp` 내부 `Item` 레지스트리만 확장하면 되며, Domain·CLI 레이어는 건드리지 않는다.

## 3. 기능 요구사항 (RED 계약)

### 3.1 등록·변환

| 연산 | 입력 | 기대 결과 | 허용 오차 |
|------|------|-----------|-----------|
| `registerUnit("cubit", 0.4572)` | 1 cubit = 0.4572 m | 등록 직후 변환 가능 | — |
| `convert("cubit", 1.0, "meter")` | — | `0.4572` | ±1e-5 |
| `convert("meter", 1.0, "cubit")` | — | `1/0.4572 ≈ 2.1872` | ±1e-5 |
| `convert("cubit", 1.0, "feet")` | meter 허브 | `0.4572 × 3.28084 ≈ 1.4997` | ±1e-5 |

### 3.2 제약

| 제약 | 내용 |
|------|------|
| **Item 수정 금지** | `UnitConverter.cpp` 및 BCE Domain(`LengthQuantity` 등) **미변경** — `Item`은 `DecayingUnit.cpp` anonymous namespace에만 존재 |
| **비율 검증** | `meters_per_unit > 0` 아니면 `std::invalid_argument` (Domain의 `InvalidMetersPerUnitError`와 **별도** 계약) |
| **기본 단위** | meter(1.0), feet(0.3048), yard(0.9144) 부트스트랩 |
| **convertAll** | source 단위 제외, 등록된 **모든** 대상 단위 반환 |

### 3.3 변환 모델 (GREEN 시)

meter 허브 공식 (BCE `ConversionEngine`과 동일):

\[
\text{result} = \text{value} \times \frac{k_{\text{from}}}{k_{\text{to}}}
\]

여기서 \(k\) = `meters_per_unit` (1 단위당 미터 수).

## 5. Bonus RED 테스트 명세

**Catch2**: `TEST_CASE("감쇠 단위 변환", "[bonus]")` — SECTION으로 BT 분리

| Test ID | Given | When | Then | 보호 Invariant |
|---------|-------|------|------|----------------|
| **BT-01** | 기본 3단위 + `registerUnit("cubit", 0.4572)` | `convert("cubit", 1.0, "meter")` | `0.4572` (±1e-5) | **INV-EXTEND**: 등록 직후 cubit→meter |
| **BT-02** | 동일 | `convert("meter", 1.0, "cubit")` | `1/0.4572` (±1e-5) | **INV-REVERSIBLE**: meter→cubit 역변환 |
| **BT-03** | 동일 | `convert("cubit", 1.0, "feet")` | `0.4572×3.28084` (±1e-5) | **INV-HUB**: meter 허브 교차 변환 |
| **BT-04** | 빈 컨버터 | `registerUnit("bad", -0.4572)` | `std::invalid_argument` | **INV-RATIO-POS**: 비율 > 0 |
| **BT-05** | cubit 등록 후 | `convertAll("cubit", 1.0)` | size=3, meter/feet/yard 포함 | **INV-CONVERT-ALL**: source 제외 전체 |
| **BT-06** | cubit 등록 후 | `convert("meter", 1.0, "feet")` | `3.28084` (±1e-5) | **INV-REGRESSION**: 기존 golden trio 불변 |

**헬퍼**: `makeConverterWithCubit()` — 각 SECTION마다 fresh `DecayingUnit` 인스턴스.

## 6. 계약 API

```cpp
class DecayingUnit {
public:
    DecayingUnit();
    void registerUnit(const std::string& name, double meters_per_unit);
    double convert(const std::string& from_unit, double value,
                   const std::string& to_unit) const;
    std::map<std::string, double> convertAll(const std::string& from_unit,
                                             double value) const;
};
```

**내부 (RED 스켈레톤만 존재)**:

```cpp
struct Item {
    std::string name;
    double meters_per_unit;
};
// Impl: vector<Item> — meter, feet, yard 기본 3건
```

## 12. 결론

`DecayingUnit` Bonus 모듈에 대해 **BT-01~06 RED 테스트**와 **실패 스텁**을 추가하였다. 빌드는 성공하고 **6개 assertion이 모두 FAIL**하여 TDD RED 단계가 충족되었다. GREEN 구현은 `DecayingUnit.cpp`의 `Item` 레지스트리와 meter 허브 변환만 확장하면 되며, 기존 BCE·CLI 경로는 격리된다.
