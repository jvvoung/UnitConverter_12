## 4. TDD RED 워크플로 반영 상세

### 4.1 C2C Traceability (README 고정)

```text
Concept → Failing Test(RED) → Minimum Implementation(GREEN) → Refactoring → Git commit
```

연결 규칙: **PRD invariant → Catch2 `TEST_CASE` 제목/태그 → 커밋 메시지**

### 4.2 5단계 매핑 (교육 슬라이드 → UnitConverter)

| 단계 | UnitConverter 대응 | README 표기 상태 |
|------|-------------------|------------------|
| ① 개념 정의 | `LengthQuantity`, `MetersPerUnit`, `UnitCatalog`, `ConversionEngine` | **진행 중** |
| ② 실패 테스트 | Catch2 환산·POL-NEG·파싱, `ctest` 의도적 FAIL | **진행 중** |
| ③ GREEN | RED TC만 통과하는 최소 Domain/Boundary | 다음 |
| ④ REFACTOR | Catalog 단일 출처, Formatter, `config/units.json` | 다음 |
| ⑤ Git | `test: … RED` → `feat: … GREEN` | 다음 |

### 4.3 README에 포함된 Catch2 RED 스니펫 (목표 계약)

| TEST_CASE | 태그 | 검증 요약 |
|-----------|------|-----------|
| `meter 2.5 converts to feet 8.2 at 1dp` | `[domain][red]` | `bootstrap_default_three_units`, feet `WithinAbs(8.2, 0.05)` |
| `meter:-2.5 rejected before conversion` | `[boundary][red]` | exit `1`, stderr `Value must be positive: -2.5\n` |

README에 **추가 RED 후보**로 명시: yard `2.7`, feet↔yard meter 경유, `LengthQuantity::create` 음수/0 실패.

### 4.4 Cursor 프롬프트 (README 템플릿)

1. **① 개념**: PRD §4.2 BCE Domain Entity, 헤더 스켈레톤만, GREEN 로직 금지  
2. **② RED 테스트**: PRD §5.1·§4.3 Catch2 Domain TC, 구현 없이 FAIL 확인

## 11. 결론

`README.md`는 [PRD](../docs/PRD.md) 정본과 동기화된 채, **TDD RED 단계(① 개념 · ② 실패 테스트)** 에 맞는 **학습 워크플로 문서**로 전환되었다. C2C·5단계 TDD·Cursor AI·Catch2 예시가 텍스트만으로도 실습 가능하도록 정리되었고, **구현 미완료**는 문서↔구현 갭 표와 RED FAIL 안내로 명확히 구분한다.
