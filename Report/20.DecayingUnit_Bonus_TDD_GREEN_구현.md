## 1. Executive Summary

[RPT-19](./19.DecayingUnit_Bonus_RED_테스트작성.md)에서 확정된 Bonus RED(BT-01~06, 6 assertion FAIL)에 대해 **`src/DecayingUnit.cpp` 단일 파일** 최소 GREEN을 수행하였다. OCP(Open-Closed Principle)에 따라 기존 `Item` 벡터(meter/feet/yard)는 수정하지 않고, **`std::map` 기반 `registry`** 에만 동적 단위를 등록한다. meter 허브 변환·`convertAll`·음수 비율 거부·기존 meter→feet 회귀가 모두 통과한다.

| `convert` | 항상 `0.0` | ✅ meter 허브 `value × (k_from / k_to)` |

## 3. 구현 접근 — OCP UnitRegistry

### 3.1 설계 원칙

| 원칙 | 적용 |
|------|------|
| **Open-Closed** | 기존 `vector<Item> units`(meter/feet/yard) **수정 없음** — 동적 단위는 `registry` Map에만 추가 |
| **Item 불변** | `struct Item { name; meters_per_unit; }` 정의·초기값 **RED와 동일** |
| **조회 순서** | `lookupMetersPerUnit`: `registry` → `units` 순 — 등록 단위가 우선 |
| **변환 모델** | BCE `ConversionEngine`과 동일: `value × (k_from / k_to)` |

### 3.2 Impl 구조 (GREEN)

```cpp
struct DecayingUnit::Impl {
    std::vector<Item> units{
        {"meter", 1.0},
        {"feet", 0.3048},
        {"yard", 0.9144},
    };
    std::map<std::string, double> registry;  // registerUnit 전용 (OCP 확장)
};
```

### 3.3 메서드 동작

| 메서드 | GREEN 동작 |
|--------|------------|
| `registerUnit(name, k)` | `k > 0` 아니면 `std::invalid_argument`; `registry[name] = k` |
| `convert(from, value, to)` | `k_from`, `k_to` 조회 후 meter 허브 곱셈 |
| `convertAll(from, value)` | `units` + `registry` 순회, `from` 제외, 각 대상에 `convert` 위임 |
