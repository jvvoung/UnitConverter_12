## 4. 결함 분석 (기대/실제 · 위치 · 심각도)

### 4.1 활성 결함 — 없음 (BCE·Catch2)

현재 `ctest` 실패 0건. **수정 diff 적용 불필요.**

### 4.2 과거 RED 이력 — D-01 (수정 완료)

`build/Testing/Temporary/LastTestsFailed.log`에 아래 TC가 과거 실패로 기록되어 있었으나, **현재 GREEN**.

| 테스트 | 기대 | RED 시 추정 실제 | 위치 | 심각도 |
|--------|------|------------------|------|--------|
| `test_convert_largeValue_returnsFiniteResult` | `isfinite(result)` | `Inf` (overflow) | `tests/domain_boundary_tests.cpp:28` | **Major** |
| `test_convert_maxFiniteValue_staysWithinDoubleRange` | finite 결과 | `Inf` | `tests/domain_boundary_tests.cpp:93` | **Major** |

**근거**: `1e308` 또는 `1e200` × `3.28084`는 double 범위 초과 → `Inf`. test_plan BV-02 권장 (B)에 따라 입력을 `1e50` / `1e100`으로 조정.

**적용된 최소 수정** (참고):

```diff
- const double large = 1e308;
+ const double large = 1e50;

- const double max_val = 1e200;
+ const double max_val = 1e100;
```

```diff
     } catch (...) {
         std::cerr << "Invalid number: " << valueStr << std::endl;
         return 1;
     }

+    if (value <= 0.0) {
+        std::cerr << "Value must be positive: " << value << std::endl;

+    }
```

**제약 준수**: Item/Domain 구조체 변경 없음 · if-else 분기 유지 · 최소 4행 추가.

`UnitConverter.cpp`에 half-up 로직을 중복 구현하지 않고, [06 보고서 §10 #1](./06.Catch2_TDD_GREEN_구현.md)대로 `ConversionApplicationService` + `TableFormatter::roundToOneDecimalHalfUp()` 연동.

**목표 stdout** (`meter:2.5`):

```text
2.5 meter = 8.2 feet
2.5 meter = 2.7 yard
```

(source unit 행 제외 · 1dp half-up)
